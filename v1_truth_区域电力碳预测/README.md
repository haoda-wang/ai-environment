# v1_truth · 区域电力碳预测（真实数据版）

> V1 的实战版：用**国家统计局真实数据**重跑「数据 → 特征 → 模型 → 评估」全流程。
> 练手版见 `v1_virtual`；本版本的指标才是能写进报告的。

## 项目定位

| 版本 | 数据 | 目的 | 状态 |
|---|---|---|---|
| v1_virtual | 合成 90 天用电量 | 练手：走通全流程 | ✅ 已完成 |
| **v1_truth**（本目录） | 国家统计局月度真实数据 | 实战：指标可写进报告 | 🔨 进行中 |

## 一句话思路

**碳排放 = 活动数据 × 排放因子** —— 本版本以全国月度发电量为活动数据，火电占比决定电力碳强度。

## 数据源

- **来源**：国家统计局月度数据（data.stats.gov.cn）
- **范围**：2015年1月 — 2026年8月（最新月份有发布延迟，属正常现象）
- **指标**（6 个，均为当期值，单位：亿千瓦时）：发电量、火力、水力、核能、风力、太阳能
- **预测对象**：暂定发电量总量（生产侧口径）；若后续补到「全社会用电量」月度数据则切换为消费侧

### 已知数据特性（侦察结论）

| 特性 | 说明 | 对策 |
|---|---|---|
| 1-2月合并发布 | 春节漂移导致统计局不单发 1 月（早年 2 月口径不一致，待验证） | step4 缺失处理时定方案 |
| GBK 编码 | 直接 read_csv 报 UnicodeDecodeError | `encoding='gbk'` |
| 宽表 | 指标在行、月份在列 | 转置 |
| 月份倒序 | 2026年9月在最左 | 排序 |
| 中文表头 | `2026年8月` 字符串 | 正则提取 + to_datetime |
| 首尾垃圾 | 前 2 行说明、尾 2 行注释、末尾空列 | skiprows + 删除 |
| 制表符污染 | 列名和数值里混有 `\t`，数值被读成字符串 | strip + to_numeric |

## 方法链条

```
干净数据(step1) → 建模矩阵(step2) → 4模型指标对比(step3) → main 一键复跑 →
火电×排放因子碳核算 → 一页技术报告
```

> 经验法则：文件超过 ~150 行考虑拆；改一个功能要动 3 个文件说明拆错了。

## 与 v1_virtual 的关键差异

1. **月频数据**：季节周期是 `lag_12`（年周期），不是 `lag_7`（周周期）
2. **真实缺失**：1-2月缺口是业务规则（春节合并发布），不是随机噪声
3. **函数化组织**：每个文件 = 可 import 的函数 + `if __name__ == '__main__'` 门卫，杜绝 import 副作用
4. **3+1 职责结构**：数据 / 特征 / 模型 / main 总开关，替代 v1_virtual 的 10 文件教学脚手架
5. **原始数据只读**：一切清洗在代码里做，换数据不换逻辑
