# v1_truth · 区域电力碳预测（真实数据版）

> V1 的实战版：用**国家统计局真实月度数据**重跑「数据 → 特征 → 模型 → 评估」全流程。
> 练手版见 `v1_virtual`；**本版本的指标才是能写进报告的**。

## 项目定位

| 版本 | 数据 | 目的 | 状态 |
|---|---|---|---|
| v1_virtual | 合成 90 天用电量 | 练手：走通全流程 | ✅ 已完成 |
| **v1_truth**（本目录） | 国家统计局月度真实数据 | 实战：预测火电 → 碳排闭环 | � 接近封版 |

## 一句话思路

**碳排放 = 活动数据 × 排放因子**
→ 预测全国月度**火电发电量**（活动数据中碳强度最高的部分）
→ × 火电排放因子 → 得到电力碳排序列

> 关键决策：不预测总发电量，直接预测**火电**，因为非化石能源（水/核/风/光）几乎不产生 CO₂，预测火电 → 乘因子即可闭环"碳预测"。

## 数据源

- **来源**：国家统计局月度数据（data.stats.gov.cn）
- **范围**：2015 年 1 月 — 2026 年 9 月，共 **141 个月**
- **指标**（12 个，单位：亿千瓦时）：发电量 / 火力 / 水力 / 核能 / 风力 / 太阳能，每个都有两套：

| 系列 | 列名 | 用途 |
|---|---|---|
| **当期值** | `total` `thermal` `hydro` `nuclear` `wind` `solar` | 建模主序列（当月发电量） |
| **累计值** | `total_cum` … `solar_cum` | 补 1-2 月缺口：`2月累计值 = 1-2月合计真值` |

- **预测对象**：`thermal`（火电当期值）→ × 排放因子 → 碳排

## 数据特性与处理（侦察结论 · 已全部落地）

| 特性 | 说明 | 对策 |
|---|---|---|
| 宽表 | 指标在行、月份在列 | `.T` 转置 |
| 月份倒序 | 2026年9月在最左 | `sort_index()` |
| 中文表头 | `2026年8月` 字符串 | 替换「年/月」后 `to_datetime` |
| 首尾垃圾 | 前 2 行说明、尾 2 行注释、末尾空列 | `skiprows=2` + `iloc[:12]` + 删 `Unnamed` |
| 制表符污染 | 列名 `指标\t`、数值 `3653.8\t` | 列名 `strip()`（**必须在 set_index 之前**）+ `to_numeric` |
| 指标交错 | 当期/累计在行上交错排列 | 按文件顺序显式命名 12 列 |
| 编码 | 实测 **UTF-8**，无需指定 `encoding`（最初误判 GBK） | 报错才加参数，不预先假设 |

## 数据体检（全量核对，非抽样）

### 有效值统计（141 行 × 12 列）

| 列 | 有效值 | 缺失 |
|---|---|---|
| total / thermal / hydro / nuclear / wind | 118 | **23** |
| solar | 105 | **36** |
| *_cum（5 列） | 129 | **12** |
| solar_cum | 115 | **26** |

**缺失规律**：

1. **当期值缺每年 1、2 月**（统计局 1-2 月合并发布，11 年无一例外）；2015-02 是唯一例外（当年单独发布）。
2. **累计值只缺每年 1 月**（1 月单独值不发布），2 月起就有值 → 所以 `2月累计值` 就是 1-2 月合计。
3. **solar 晚 1 年上线**：2016-05 才有第一个值（32.8），2016 年约 30、2026 年已到 700 —— 是真实的光伏装机爆发，**不是数据错误**。
4. **2015-01 可精确还原**：`total_cum(2015-02) − total(2015-02) = 8560.9 − 3653.8 = 4907.1`，用当期+累计交叉，把一个"缺失"变成"可算的真值"。

### 交叉验证：当期 vs 累计

`累计值(本月) − 累计值(上月)` 应等于 `当期值(本月)`。全量统计结果：

| 指标 | 平均偏差 | 最大偏差 |
|---|---|---|
| total | 58.02 | 266.70 |
| thermal | 31.75 | 226.50 |
| hydro | 6.31 | 69.90 |
| nuclear | 0.60 | 18.60 |
| wind | 15.56 | 95.00 |
| solar | 13.99 | 85.90 |

**结论**：两套数据并非严格恒等，原因是统计局对当期值和累计值**分别修订**。相对偏差约 0.8%，量级可接受。
最大偏差多落在 11 月（年度修订窗口），不影响用 2 月累计值补 1-2 月。

> **教训（重要）**：我最初只抽查 3 个月（最大偏差 41.6），据此判断"偏差约 0.5%"；全量统计后发现最大值 266.7。**抽样 3 个点不代表全貌，数据体检必须全量跑。**

### 数据内部自洽性

`total ≈ thermal + hydro + nuclear + wind + solar`。抽查 2026-08：五类之和 9437.7 vs total 9437.8 ✅；2015-03 差 60.8 正好是 solar 空值。

### 报告素材：火电占比持续下降

| 时间 | 火电 / 总发电 |
|---|---|
| 2015-03 | 77.5% |
| 2020-08 | 70.3% |
| 2026-08 | **63.8%** |

11 年降约 14 个百分点 → 碳核算环节的天然叙事：**发电量在涨、火电占比在跌，碳排放增速低于发电增速**，即电力结构低碳转型。

## 特征工程（step2）

### 1-2 月缺失填补（`fill_jan_feb`）

核心思路：**用 2 月累计值（真值）拆分 1 月和 2 月**，而非插值编数字。

| 情况 | 处理 |
|---|---|
| 有 2 月当期值（仅 2015） | `1月 = 2月累计 − 2月当期`（精确还原） |
| 无 2 月当期值（其他年份） | 按天数比例拆分：`1月 = 累计 × 31/(31+28)`，`2月 = 累计 − 1月`（闰年代 29） |

### 滚动特征 & 防泄漏

- **lag1**（上月值）、**lag12**（去年同月值，捕捉年周期）
- 所有 lag 特征**先 `shift` 再 roll**，杜绝未来数据泄漏
- 窗口起点：**2017-01-01**（因 solar 2016-05 才上线，2017 起五类齐全）

### 共线性处理（关键决策）

最初构造了 6 个 lag1（total + 5 个分项），但 `total = thermal + hydro + nuclear + wind + solar` 完全线性相关 → 线性回归权重爆到 ±505。
**对策**：删掉 5 个分项 lag1，只保留 3 个特征：

```
X = [thermal_lag1, thermal_lag12, month]
```

## 模型对比（step3）

四模型：基线(上月值) / 线性回归 / 随机森林 / XGBoost，统一用 MAPE（×100，百分比）。

### 预测 total（发电量总量）的结果

| 模型 | MAPE |
|---|---|
| 基线（上月值） | 7.51% |
| 线性回归 | **2.24%** 🏆 |
| 随机森林 | 2.98% |
| XGBoost | 3.07% |

**线性回归最优**，权重 `[0.1707, 0.8528, 6.4791]`，截距 119.79：
→ 下月预测 ≈ `0.17 × 上月 + 0.85 × 去年同月 + 6.48 × 月份 + 119.8`

### 预测 thermal（火电）的结果

| 模型 | RMSE | MAE | MAPE |
|---|---|---|---|
| 基线（上月值） | 575.49 | 476.79 | 9.06% |
| **线性回归** 🏆 | 276.08 | 202.14 | **3.92%** |
| 随机森林 | 287.60 | 214.97 | 4.18% |
| XGBoost | 421.04 | 316.88 | 6.25% |

**观察**：
- 预测火电比预测总发电量难（线性 MAPE 2.24% → 3.92%）：火电受来水、煤价、检修影响波动大，总量有平滑效应。
- 线性回归依然最优：~100 个训练点 + 3 个特征，复杂模型（XGBoost 6.25%）反而过拟合。

## 碳核算（main.py）

**公式**：

```
碳排(万吨 CO₂) = thermal(亿kWh) × 排放因子(kgCO₂/kWh) × 10
```

- 单位推导：1 亿 kWh × 1 kgCO₂/kWh = 1 亿 kg = **10 万吨** CO₂，所以乘 10
- **排放因子 ≈ 0.8333 kgCO₂/kWh**（化石能源电力因子，火电专用）
- 来源：生态环境部 + 国家统计局《2022 年电力二氧化碳排放因子公告》
- ⚠️ 电网平均因子 ≈ 0.5366 用于「用电量」口径，与火电因子**不可混用**

**示例**：2026-08 火电 6020.3 亿kWh → 碳排 = 6020.3 × 0.8333 × 10 ≈ **33111.65 万吨 CO2**

### 年度碳排放（真值换算，亿吨 CO2）

| 年份 | 碳排(亿吨) |
|---|---|
| 2015 | 31.42 |
| 2016 | 30.76 |
| 2017 | 32.22 |
| 2018 | 34.20 |
| 2019 | 35.62 |
| 2020 | 37.23 |
| 2021 | 40.05 |
| 2022 | 40.36 |
| 2023 | 43.57 |
| 2024 | 43.71 |
| 2025 | 43.78 |
| 2026 | 30.55（仅 1-9 月，不可与完整年直接比） |

**叙事**：2015→2025 火电碳排 +39%（31.4→43.8 亿吨），但同期火电占比从 77.5% 降至 63.8% → **总发电量涨得比碳排快**，能源结构低碳转型的证据。

年度汇总代码：`df['carbon'].resample('YE').sum() / 1e4`（万吨 → 亿吨）

## 与 v1_virtual 的关键差异

1. **月频数据**：季节周期是 `lag_12`（年周期），不是 `lag_7`（周周期）
2. **真实缺失**：1-2 月缺口是业务规则（春节合并发布），不是随机噪声
3. **函数化组织**：每个文件 = 可 import 的函数 + `if __name__ == '__main__'` 门卫，杜绝 import 副作用
4. **3+1 职责结构**：数据 / 特征 / 模型 / main 总开关
5. **原始数据只读**：一切清洗在代码里做，换数据不换逻辑

## 关键决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 数据地域 | 全国（不限沈阳/辽宁） | 官方口径统一、粒度稳定、双碳叙事直接 |
| 只下「当期值」→ 补下「累计值」 | 两套都下 | 当期值管建模，累计值补 1-2 月缺口，还能交叉验证 |
| 1、2 月缺口方案 | **A：用累计值补** | 拿到的是真值合计，比插值编的数字靠谱 |
| 原始 CSV 处理 | 代码里 `skiprows`，不手删 | 换数据不换逻辑；原始文件是"案发现场" |
| 特征集 | 只保留 lag1 + lag12 + month | 删掉分项 lag1 解共线性（权重爆 ±505） |
| 建模窗口 | 2017-01 起 | solar 2016-05 才上线，2017 起五类齐全 |
| 预测对象 | thermal（火电）而非 total | 非化石能源近零碳，预测火电直接闭环碳预测 |
| 排放因子 | 火电 0.8333 kgCO₂/kWh | 化石能源电力因子，区别于电网平均 0.5366 |
| CV 策略 | `TimeSeriesSplit(n_splits=3)` | 禁止默认 KFold（会打乱时序） |

## 踩坑实录

1. **`iloc[:6]` 补下累计值后静默切错**：文件从 6 行变 12 行，切片不报错但后 3 个指标全丢、列名错位 → **列数变化后必须检查 shape 和列名**
2. **`strip()` 必须在 `set_index` 之前**：转置后月份变成 index，就再也没机会 strip 了
3. **编码不要预设**：一开始按"国内官方导出多为 GBK"加了 `encoding='gbk'`，实际是 UTF-8，反而多余
4. **抽查不能代替全量**：3 个月抽查得出"偏差 0.5%"，全量后最大 266.7
5. **共线性让线性回归权重爆 ±505**：`total_lag1` 与 5 个分项 lag1 完全线性相关 → 删分项，只留 lag1 + lag12 + month
6. **MAPE 忘 ×100**：`mean_absolute_percentage_error` 返回小数，显示要 ×100 才是百分比
7. **RMSE 别名误用**：不能 `from sklearn.metrics import mean_squared_error as rmse`，要用 `np.sqrt(mse)`
8. **matplotlib y 轴污染**：永远 `plt.plot(x.to_numpy(), y.to_numpy())`，否则 index 会被当成 y 值
9. **import 副作用**：所有脚本包 `if __name__ == '__main__'`，否则 import 时就执行了
10. **手动删 CSV 禁止**：原始数据只读，处理全在代码里
11. **列名写死导致 target 切换错位**：`run_all` 里 `x_test['total_lag1']` 要改成 `f'{target}_lag1'`，否则切到 thermal 就 KeyError
